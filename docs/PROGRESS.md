### Setting up a new machine
1. Install Flutter **3.47.8 stable** (or `dart pub global activate fvm`, then `fvm install 3.47.8` in `apps/mobile_flutter`).
2. Android Studio with SDK platform 36 and build-tools 36, then `flutter doctor --android-licenses`. `flutter doctor -v` should show no issues.
3. Optional, for Claude Code: the `dart-flutter` plugin and Dart MCP server (plan §8).
4. `cd apps/mobile_flutter && flutter pub get && dart run build_runner build && flutter analyze && flutter test`
   should show 0 issues and 92 passing tests. The models are generated: without `build_runner` nothing compiles.
5. Start the API (root `README.md`), then `flutter run --dart-define=API_BASE_URL=http://10.0.2.2:4000` (emulator)
   or use the PC's LAN IP (phone).

### Next steps, in order
1. **Run it against a real server on a real phone.** Everything so far is checked by the analyzer and by widget
   tests against a fake HTTP adapter; no screen past phase 1 has been seen on a device. Seed the API, build the
   debug APK, and walk the whole thing: Discover, a host page, an event, save, follow, sign up, claim a handle,
   post an event, upload a poster.
2. **Confirm the reminders actually fire.** Save an event starting in a little over an hour and leave the phone
   alone. Background sync and local notifications are the one part no test can prove.
3. **Set `appLinkHost` and publish `assetlinks.json`** once the production domain is settled, or App Links stay
   unverified and keep opening in the browser. iOS Universal Links also need the entitlement and an
   `apple-app-site-association` file.
4. Then the two owner decisions under Open items, and a Play Store internal testing build (plan §10, phase 7).
